# Graphics

PAL low-resolution 320×256, three bitplanes laid out as three contiguous 10 240-byte planes
(40 bytes per line), so eight colours.

| Plane | Content | Lines |
| --- | --- | --- |
| 0 | Generated `NEON VECTORS` logo | 48–111 |
| 1 | Scroller, double height | 210–225 |
| 2 | 32 one-pixel stars | 128–191 |

Palette: `COLOR00` background plus animated bands from the Copper; `COLOR01` white (logo),
`COLOR02` cyan (scroller), `COLOR04` light blue (stars).

## Logo

Generated by `tools/generate_assets.py` from an embedded 5×7 glyph set drawn at 4× with a 6-pixel
advance: twelve characters occupy 284 pixels, centred at x = 18, with two rules and corner marks.
The validator requires all ink to stay inside x = 1..318 so the logo can never be clipped.

## Stars

Each star is an (x, row offset) pair, where the row offset is `y * 40` and y is 128–191. x starts
at `73·i mod 320` and increases by one pixel per frame, wrapping at 320. The byte within the row is
`x/8` and the bit is `7 − (x mod 8)`; `StarAddress` derives it with an indexed `LEA` and never
modifies the plane base, which the caller reuses for all 32 stars. Drawing is two passes — erase
every star, then advance and draw — so two stars that share a byte cannot erase each other, and
x is advanced before drawing so the next erase always hits exactly the pixel that was drawn.

## Scroller

Planar pixels are MSB first, so scrolling left shifts each row as big-endian longwords from the
rightmost to the leftmost with `ROXL`: bit 31 of one longword falls into X and enters the next
longword to its left at bit 0. X must start at zero for each row, and `MOVEQ` does not touch it, so
it is cleared explicitly with `andi #$EF,ccr`; the intervening `MOVE`, `SUBQ` on an address register
and `DBRA` leave it alone. A longword chain does the work of the word loop in about 60 % of the
cycles, which keeps the frame inside the vertical-blank window.

Every second frame the band moves one pixel, then the next column of the current glyph is
written into bit 0 of the last byte of each of the 16 rows (each of the 8 font rows on two lines).
After eight columns the pointer advances; a zero terminator wraps the text. Characters outside
32–126 render as blanks.

`tools/emu_test.py` compares the whole band with the expected text drawn from `font.raw`,
pixel for pixel.

## Copper and display setup

The Copper sets display fetch/window registers, `BPLCON0` (three planes), the six pointer pairs,
the palette and six colour changes at lines 128–168. `PatchCopper` writes the runtime chip
addresses into the pointer *data* words (offsets 2/6, 10/14, 18/22 from `cop_bpl1`) and leaves
the register words alone.
